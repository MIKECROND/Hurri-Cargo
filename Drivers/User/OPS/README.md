# Drivers/User/OPS · 平面定位模块（OPS）

> 对应实现：`ops.c/.h`、`ops_cfg.h`（配置唯一来源，本轮禁改）。

## 1. 职责

通过 UART4 接收 OPS（定位系统）下发的 24 字节定位帧，解析出平面坐标/航向等数据，
并提供**数据新鲜度**判定供导航层使用。本模块是导航链路上游，只做"收帧 + 解析 + 新鲜度"，
不参与控制决策。

| 文件 | 职责 |
| :- | :- |
| `ops.h` | 对外接口：定位数据结构 `OPS_Data_t`、收帧/取数/新鲜度 API |
| `ops.c` | UART4 空闲中断 DMA 收帧、帧界状态机、解析、新鲜度维护 |
| `ops_cfg.h` | 帧长/字段下标/波特率/超时等配置（**禁改**） |

## 2. 关键参数边界

- 帧格式：**24B 定长帧**，帧头帧尾、字段下标、解析状态机全部来自 `ops_cfg.h`，属实车协议契约。
- 波特率：UART4 波特率由 `ops_cfg.h` / CubeMX 配置决定，**不改**。
- 新鲜度：`OPS_GetFrameAgeMs()` 基于 `s_last_frame_tick` 计算帧龄，导航侧 `150ms` 超时判定依赖其语义，**不改**。
- 缓冲区：`USART4_RX_BUF_SIZE` 等结构性容量可保持原值整理，不改数值。

所有上述数值、符号、量纲来自实车整定；改动即改变可观测行为。

## 3. 禁止改动项（红线）

- 24B 帧解析状态机、帧界（帧头/帧尾）、字段偏移与字节序：不改。
- `OPS_GetFrameAgeMs()` / `s_last_frame_tick` 的新鲜度语义与 `150ms` 超时口径：不改（审计已修项，勿回退）。
- UART4 DMA 接收与回调注册、波特率：不改。
- `ops_cfg.h`：整体只读。

## 4. 调试入口

- 导航侧通过 `nav par` / `mission time` 观察定位与耗时；OPS 数据新鲜度异常会在导航日志中体现为"OPS stale"。
- 定位数据由导航任务消费；本模块不单独注册 shell 命令，收帧状态在有错误时经 `logWarning` 输出（如 RX 队列溢出丢帧计数）。

## 5. 验证方式

无独立主机 harness。行为保持以静态审阅 + `git diff` 逐行核对 + `tools/check_refactor.py --check all` 门禁为准；
协议字节/帧界/新鲜度数值以数字 token 多重集与 HEAD 比对，确保零变化。
