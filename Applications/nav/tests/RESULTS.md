## 2. 基线 / 改动前后对比（13 场景平均）

场景：直线 100cm\@30/50/70/100cm/s、短距 5cm、斜向、原地 90°/180°、PASS 不停车换目标、PASS 过弯、
连续 3 点。命令延迟 = 电机总线端到端纯延迟。模型默认：τ=60ms、OPS 50Hz/20ms、rpm 量化开、无打滑。

|  命令延迟 | 基线 到位时间 | 当前 到位时间 | 基线 最终位置误差 | 当前 最终位置误差 | 基线 平均超调 | 当前 平均超调 | 基线 未到达 | 当前 未到达 |
| ----: | ------: | ------: | --------: | --------: | ------: | ------: | -----: | -----: |
|   0ms |   2.33s |   2.72s |    0.38cm |    0.37cm |  2.12cm |  2.12cm |      0 |      0 |
|  10ms |   2.33s |   2.79s |    0.56cm |    0.54cm |  2.24cm |  2.25cm |      0 |      0 |
|  20ms |   2.34s |   2.99s |    0.83cm |    0.78cm |  2.57cm |  2.57cm |      0 |      0 |
|  50ms |   2.75s |   3.86s |    0.56cm |    0.55cm |  3.36cm |  3.35cm |      0 |      0 |
| 100ms |   3.06s |   4.88s |    0.23cm |    0.22cm |  5.20cm |  5.22cm |      0 |  1(超时) |

**结论**

1. **命令延迟的影响是量化的**：直线段 0→100ms 延迟，单次到位超调从 0.1\~0.5cm 增大到 4.6\~5.7cm
   （例如 `line100_70`：0.11→4.87cm；`line100_100`：0.33→5.65cm），到位时间 +32%（基线）/+79%（当前）。
   两个版本都能靠"判到不准则恢复 RUNNING 补位"把最终位置误差收回到 ≤0.6cm；**代价是时间**。
   延迟 >50ms 后时间明显变差 → 电机总线修复目标（<15ms）非常重要。
2. **当前改动的收益主要体现在航向精度/高延迟稳定性**：d=100ms 时基线 yaw 误差平均 1.58°
   （rot180 实测 4.38°、rot90 3.71°、line100\_yaw90 4.13°），当前版 0.26°（rot180 0.30°、rot90 0.01°）；
   代价是到位时间 +17%~+59%，且 d=100ms 时 `line100_yaw90`（边走边转 90°）会超时。
3. **延迟 100ms 尚未出现"发散振荡"**，但已出现：超调 5cm 级、rot90/rot180/seq\_3pt 的 STOPPING 反复
   复核/补位（`near_osc` 5\~6 次、单段耗时 7.6\~9.8s）。若实车命令延迟 >50ms，`STOPPING` 的复核/补位
   逻辑会明显拖慢任务时间。
4. **当前版 d=0 比基线慢 +17%（2.72 vs 2.33s）**：模型里主要表现为 STOPPING 复核要看 OPS 位姿是否停稳，
   而 OPS 有 20ms 延迟/50Hz 保持，最后距离判据可能读到"停车前一帧"的旧位置 → 判定不达标 → 恢复 RUNNING
   再补一次，多耗 400\~700ms。**建议**：STOPPING 复核显式使用 OPS `OPS_GetFrameAgeMs()`，
   等新帧（或按帧龄加容差）再判，避免用旧帧误判触发补位循环。
5. **STOPPING stop\_settle\_ms = 150 是安全的**（quick 套件，当前代码）：

| stop\_settle\_ms |      平均时间 |      平均位置误差 |     最大位置误差 | 平均 yaw 误差 | 最大 yaw 误差 | STOPPING 尾延迟 |
| ---------------: | --------: | ----------: | ---------: | --------: | --------: | -----------: |
|              100 |     2.95s |     0.428cm |     1.03cm |     0.06° |     0.34° |       1105ms |
|      **150（默认）** | **3.05s** | **0.423cm** | **1.03cm** | **0.08°** | **0.35°** |   **1210ms** |
|              200 |     3.15s |     0.425cm |     1.03cm |     0.07° |     0.35° |       1310ms |
|              300 |     3.36s |     0.423cm |     1.03cm |     0.06° |     0.35° |       1516ms |

150ms 与 200/300ms 的最终位置/yaw 误差在数值噪声内等价（位置差 <0.005cm、yaw 差 <0.02°），
但每段节省约 0.1s/0.3s。**结论：保持 150ms。** 100ms 也几乎没有精度损失、再省 0.1s，
但余量偏小（打滑/滑移模型一变就可能不够），不主动建议。

## 3. 运行时整定参数敏感度（`--tune`，quick 套件，综合代价比 <1 更好）

综合代价 = 到位时间(s) + 2×位置误差(cm) + 0.05×yaw误差(deg) + 0.3×超调(cm) + 0.1×振荡次数。

| 参数                           | 取值=代价比（\*\*=最优）                       | 极差/最优 | 结论                            |
| ---------------------------- | ------------------------------------- | ----: | ----------------------------- |
| `traj_speed_cap`             | 30=1.025 / **50=1.000** / 80=1.081    |  8.1% | 默认 50 最佳；提高到 80 明显变差（近目标速度太高） |
| `near_gain`                  | 1.5=1.027 / **3.1=1.000** / 5=1.069   |  6.9% | 默认 3.1 最佳                     |
| `yaw_kp`                     | 1.2=1.022 / 1.8=1.000 / **2.4=0.982** |  4.1% | 2.4 略优（-1.8%），收益小             |
| `xy_kp`                      | **0.8=0.980** / 1.2=1.000             |  2.0% | 0.8 略优（-2.0%），收益小             |
| `yaw_max_speed`              | 60=1.018 / **100=1.000**              |  1.8% | 保持默认 100                      |
| `yaw_kd`                     | 0.3=1.015 / **0.6=1.000**             |  1.5% | 保持默认 0.6                      |
| `align_dist`                 | 3=1.000 / 5=1.000                     |    0% | 不敏感                           |
| `startup_speed`              | 1.0=1.000 / 1.5=1.000                 |    0% | 不敏感                           |
| `NAV_ARRIVE_CHECK_COUNT`     | 宏扫描 1/2/3：差异 <1%                      |     — | 保持 2                          |
| `NAV_YAW_ZERO_CROSS_LOCK_MS` | 宏扫描 0/8/20：差异 <1.5%                   |     — | 保持 8                          |

**推荐（仿真模型内）**：默认值基本已是最优区间，**不建议大改**；可按实车微调
`yaw_kp` 1.8→2.4、`xy_kp` 1.2→0.8（各约 -2% 综合代价，仿真收益小、实车风险需验证）。
`traj_speed_cap`/`near_gain` 保持默认（改坏的风险明显大于收益）。

## 4. 模型不确定度（结论对模型假设的敏感程度）

| 维度          | 扫描范围                         | 对结果的影响                                                                  |
| ----------- | ---------------------------- | ----------------------------------------------------------------------- |
| 轮速一阶滞后 τ    | 40/60/80/120ms（d=0/50）       | d=50 平均时间 2.91\~3.05s、平均误差 0.36\~0.54cm；超调 1.1\~1.8cm。τ 越大超调略增，量级小于命令延迟 |
| 轮地打滑        | 0/5/10%                      | 平均误差 0.36\~0.59cm（打滑会被位置环补回）；对超调影响 <0.3cm（模型为均匀缩放，真实打滑更复杂）              |
| OPS 更新率     | 20/50/100Hz（d=0/50）          | d=0 平均超调 0.02\~0.40cm、平均误差 0.34\~0.55cm；对"到位时间"影响 <5%。OPS 20Hz 时延迟效应更明显 |
| OPS 测量/传输延迟 | 5/20/50ms                    | 与命令延迟同向叠加：延迟越大，判到越晚、超调越大（详见自动报告 5.x）                                    |
| STOP 制动模型   | 800/4000/8000cm/s² × 20/60ms | **最大不确定项**：软制动(800)会显著增大超调/触发补位；真实 0xFE 立即停止的残余滑移需实车标定                  |
| 控制周期抖动      | 0\~8ms 随机@35%，d=0/20/50      | 平均时间变化 <5%，和纯延迟相比是二阶效应（但它会让 nav `dt` 抖动）                                |

## 5. 实车整定配方（上板 1 小时内，配合真实 shell 命令）

前置（5 分钟）：场地清出 ≥3m 直线；OPS 稳定（`nav pose` 读数不跳变）；`car bus`/`step bus` 确认 4 轮在线；
记录当前全部参数：`nav par`（逐行 name=value，先拍照存档）。

1. **命令时延基线（10 分钟，先确认根因是否已修）**：`step bus` 看电机应答/错误计数；跑一段 `nav goto`
   并用 `nav trace 5` 抓 CSV，看 `meas_speed` 跟随 `cmd_vx` 的滞后（上升沿延迟）。>50ms 说明总线/队列仍有问题，
   先修总线，不要先调 nav。
2. **直线阶跃（15 分钟）**：`nav par yaw_kp 1.8`（默认）下，用地图直线点（或临时点）跑 `nav goto`，
   `nav trace 20` 记录，检查：到位时间、`arrive_count` 是否被"假到点"提前触发、`meas_speed` 在最后 5cm 是否
   ≤ `traj_speed_cap`(50)。若过冲 >2cm：二分 `traj_speed_cap` 50→40（每次 -10）直到超调 ≤1.5cm。
3. **yaw 阶跃/整定（15 分钟）**：原地旋转 90°（任务 ROTATE 段或 `nav goto` 到同坐标不同 yaw 点）：
   - 欠阻尼"甩头/回摆"→ `nav par yaw_kd 0.6→0.8`（一次 +0.2，最多到 1.0）；
   - 收敛慢 → `nav par yaw_kp 1.8→2.2`（一次 +0.4；若振荡退回）；
   - 零交叉附近抖动 → 先别动 `yaw_min_speed`(3)，用 `nav trace 5` 确认是否 OPS 噪声。
4. **到位精度/STOPPING（10 分钟）**：观察到位日志是否有 "stop check failed, resume" 或
   "stop not settled, resume"：
   - 频繁 resume → `nav par stop_settle_ms 150→200`（**仿真显示 150 足够，此步仅当实车滑移大时**）；
   - 反复补位仍偏 → 检查 OPS 帧龄/延迟（`nav trace` 的 meas 与 cmd 延迟）；必要时调 `NAV_STOP_WINDOW_MOVE_CM`/
     `NAV_STOP_FRESH_OPS_MS`（生产代码宏，需 Lead 评估）。
5. **回归（10 分钟）**：跑 2~3 个真实任务段（含 PASS 过弯），对比 `nav par` 修改前后日志的
   `task_elapsed_ms`/到位误差；把最终参数记录回 `nav par` 数值，并回写给 Lead 更新默认宏。

**别一次改多个参数**：每次只改 1 个、`nav par <name> <value>` 立即生效、跑 3 次取中位数；
所有实验记录 `nav trace` CSV（`NAVTRACE,` 行可直接用 Excel 打开）。

## 6. 已知限制

- 模型是单点近似（无轮胎侧滑/车身惯性、无 OPS 丢帧，用帧龄模型代替）；STOP 制动与 τ 是两个最大不确定项。
- 场景无现场障碍、PASS 触发用 4cm 简化；不含 Planner/任务层时序。
- 当前版"到位时间变慢"的一部分是模型里 OPS 延迟与 STOPPING 复核的交互，实车 OPS 帧率/延迟不同会变化；
  该结论已按"建议 STOPPING 用 OPS 帧龄等新帧再判"的形式给出可落地改进方向。
- 本目录不改生产代码、不碰串口/烧录；构建产物只写 `%TEMP%`。

## 7. Lead 按建议修正 STOPPING 后的复跑结果（2026-11-13）

修正内容（`Applications/nav/utils/nav_core.c` + `nav_config.h`）：

- 停稳判定改为 **100ms 滑动窗口**（只比较窗口内位移/转角，>0.4cm/>1.0° 视为仍滑移），
  不再用"进入 STOPPING 以来的累计位移"（OPS 的 10\~20ms 延迟会把减速正常滑行误判成"还在动"）；
- 终判前要求 OPS 位姿足够新（`OPS_GetFrameAgeMs() <= 50ms`）；
- 复核失败恢复 RUNNING 的补位次数上限 `NAV_STOP_MAX_RESUME=3`（防止反复补位拖到超时）。

复跑命令：`run_sim.ps1 -NoSweep -NoUncertainty`（13 场景平均，同模型 A/B）：

|  命令延迟 |  基线时间 | 修正前时间 | **修正后时间** | 基线 位置误差 | **修正后 位置误差** | 基线 yaw | **修正后 yaw** |
| ----: | ----: | ----: | --------: | ------: | -----------: | -----: | ----------: |
|   0ms | 2.33s | 2.72s | **2.25s** |  0.38cm |       0.38cm |  0.16° |       0.16° |
|  10ms | 2.33s | 2.79s | **2.26s** |  0.56cm |       0.54cm |  0.26° |       0.25° |
|  20ms | 2.34s | 2.99s | **2.30s** |  0.83cm |       0.77cm |  0.40° |       0.29° |
|  50ms | 2.75s | 3.86s | **2.68s** |  0.56cm |       0.55cm |  0.55° |       0.10° |
| 100ms | 3.06s | 4.88s |     4.21s |  0.23cm |       0.25cm |  1.58° |       0.18° |

结论：

- 延迟 ≤20ms（电机命令链修复后的真实水平）时，修正后版本比基线**每段平均快 44\~78ms**，
  且位置精度持平、航向精度不劣于基线（d=20 时 yaw 由 0.40°→0.29°）。
- 延迟 50ms 时仍比基线快 68ms 且 yaw 显著更好（0.55°→0.10°）。
- 延迟 100ms（相当于回退到旧命令链）时因补位循环比基线慢，但航向精度仍大幅更好；
  该场景不是交付固件的真实延迟，仅作旧链路回退时的参考（此时建议 `stop_settle_ms` 改回 300）。
