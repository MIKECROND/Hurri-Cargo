## 9. 根因分析（人工补充；重跑 summarize.py 会覆盖本节）

1. **搜索判据的物理半径覆盖不足**：HEAD `evaluate_node_cost` 取 `r_phys_g = (int)(0.15/0.1) = 1`、`r_phys2 = r*(r+1) = 2`，
   只把 3×3 邻域（含对角）判为碰撞。车体半径实际是 1.5 格，路径格中心与障碍格中心只要求差 2 格（20cm）；
   而障碍矩形角点可深入格子内部最多半对角线 7.07cm，因此真实清障最小可到约 12.9cm。
   本报告 `raw_collision = 30/40` 说明 **A\* 原始路径输出时就已经违反 15cm 半径**，不是直线化造成。
2. **直线化会进一步切角**：`segment_is_free` 用同一套 3×3 判据 + 5cm 采样，5cm 大于“格子角部危险区”的采样分辨率，
   采样点会跳过最危险的位置。zone2 `QrCode -> MATL_PROCESSING` 从 A* 原始 14.14cm 被拉到 **11.18cm**（再损失 2.96cm），
   是最典型案例：世界坐标 (95.0, 100.0)cm 处切的是 (35..90, 35..90)cm 方框的右上角。
3. **端点精确代入 + 30cm 通道 = 零余量**：路径首末点被精确替换成起/终点坐标（`goal_error = 0`），
   本场地多条通道净宽 30cm 恰好等于车宽 30cm，名义清障正好 15.0cm；浮点误差使其在 14.99999~15.00001cm 抖动。
   报告严格按 `< 15cm` 判“碰撞”，同时单列“零余量”分类，避免把边界抖动误读为实质性穿障。

**对重构版的验收建议**：以 `min_clearance ≥ 15cm`（建议留 1~2cm 余量）为硬指标，A* 原始路径与直线化后路径都要满足；
安全性不劣化前提下，航点数/路径长度不劣化；并保留本工具相同 40 条点对的对比报告。

## 附录：CSV 字段说明

`*_zone<z>.csv`（每条点对一行）：

- `zone,start,goal`：启动区、起点名、终点名
- `ok`：A* 是否成功（0/1）
- `astar_pts`：A* 原始逐格路径点数；`waypoints`：直线化后航点数
- `length_cm`：直线化后路径总长
- `min_clearance_cm`：直线化后路径全程最小清障距离（点到障碍矩形精确欧氏距离）
- `collision`：是否 `min_clearance_cm < 15cm`（0/1）
- `min_clr_wp_idx`：清障距离最小的航点下标（辅助参考）
- `min_clr_seg`：最小清障所在路径段下标（0 基）
- `min_clr_rect`：最小清障处最近障碍矩形下标（对应 `*_rects_zone<z>.csv`）
- `min_clr_x_cm, min_clr_y_cm`：最小清障发生点世界坐标（cm）
- `segs_over_radius`：含“清障 < 15cm”采样点的路径段数
- `wp_over_radius`：清障 < 15cm 的航点数
- `goal_error_cm`：路径末点与目标点距离（应≈0）
- `max_turn_deg, sum_turn_deg`：内部航点最大转角、转角绝对值之和
- `raw_min_clearance_cm, raw_collision`：A* 原始逐格路径的同口径指标
- `raw_min_clr_x_cm, raw_min_clr_y_cm, raw_min_clr_rect`：原始路径最小清障位置与最近矩形

`*_paths_zone<z>.csv`（每个航点一行）：`wp_idx, world_x_cm, world_y_cm, clearance_cm, seg_len_cm, turn_deg`。

`*_rects_zone<z>.csv`：独立几何真值使用的障碍矩形（由旧 config.h 每 4 个障碍顶点一组构造）。
